# Enterprise BI Engine — Multi-Agent Adversarial Diagnostics Stack

**Accenture Innovation Challenge 2026 · Round 2 · BusinessIntelligence.ai**

A KPI intelligence-to-action engine. It detects material KPI movements with
deterministic statistics, links them to timestamped unstructured evidence,
resolves competing explanations through an adversarial agent debate, and —
when the evidence genuinely does not support a conclusion — **refuses to
answer**.

The architectural claim is one sentence:

> **The mathematical source of truth is SQL. The language models reason over
> numbers they cannot alter, and the decision to stay silent is enforced in
> Python, above the model layer.**

## Quickstart

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env          # optional: add OPENAI_API_KEY for a live debate
python setup_db.py            # seeds DuckDB + ChromaDB (idempotent)
streamlit run app.py
```

Verify the backend without the UI:

```bash
python agents.py 1 "VP of Revenue (Executive)"          # multi-factor incident
python agents.py 2 "VP of Revenue (Executive)"          # abstain
python agents.py 3 "Director of Engineering (Technical)"  # sparse history
pytest tests/ -q                                        # 82 acceptance tests
```

### Running without an API key

The prototype runs fully without `OPENAI_API_KEY`, in **Replay mode**, and the
UI labels every such run. This is deliberate: a demo must not depend on network
weather.

| Layer | Live mode | Replay mode |
|---|---|---|
| SQL, statistics, z-scores, driver ranking | real | **real** |
| Vector retrieval + time-window filter | real | **real** |
| RBAC access decisions | real | **real** |
| Abstain safety gate | real | **real** |
| Pydantic schema validation | real | **real** |
| Debate / narrative wording | generated by AutoGen | replayed from pre-authored text |
| Token counts | measured from the model client | estimated from transcript volume |

Replay text argues over the *same* computed numbers and cites the *same*
retrieved evidence ids as the live path. Nothing quantitative is faked; only
the language generation is. Set `OPENAI_API_KEY` in `.env` for the live path.

## The LLM boundary

This is the requirement the Round 2 brief calls the golden rule: *the LLM
should not be treated as the source of quantitative truth.* Here is the line,
drawn explicitly.

```
┌──────────────────── DETERMINISTIC (no LLM) ────────────────────┐
│                                                                │
│  config/semantic_contract.yaml   KPI definitions, thresholds,  │
│                                  lineage, access rules         │
│                                                                │
│  watcher/deterministic.py        SQL over DuckDB               │
│                                  • values, deltas, percentages │
│                                  • baseline mean / stdev       │
│                                  • z-scores                    │
│                                  • materiality (stat + impact) │
│                                  • driver attribution + rank   │
│                                  • RBAC — query suppression    │
│                                  • sparse-history degradation  │
│                                                                │
│  rag/retrieval.py                ChromaDB + time-window filter │
│                                                                │
└───────────────────────────┬────────────────────────────────────┘
                            │  bounded context object
                            │  (numbers are read-only facts)
                            ▼
┌──────────────────── LLM (bounded reasoning) ───────────────────┐
│  Researcher   summarises retrieved evidence                    │
│  Bear         argues the internal / controllable cause         │
│  Bull         argues the external / market cause               │
│  Arbitrator   returns a confidence DISTRIBUTION, not a verdict │
└───────────────────────────┬────────────────────────────────────┘
                            │
                            ▼
┌───────────── PYTHON SAFETY GATE (agents.py) — no LLM ──────────┐
│  Gate 1   confidence < 60                    → ABSTAIN         │
│  Gate 2   attribution non-separable          → ABSTAIN         │
│  Gate 3   unparsable arbitration → conf 0    → ABSTAIN         │
│                                                                │
│  On abstain the Storyteller is NEVER CONSTRUCTED.              │
└───────────────────────────┬────────────────────────────────────┘
                            │ only if all gates pass
                            ▼
┌──────────────────── LLM ──────────┐   ┌──── DETERMINISTIC ────┐
│  Storyteller  narrative + action  │──▶│  Pydantic validation  │
└───────────────────────────────────┘   │  reject, never coerce │
                                        └───────────────────────┘
```

**A language model cannot talk its way past a function it is never handed.**
Verify it yourself:

```bash
OPENAI_API_KEY=invalid python -c "
from watcher.deterministic import query_kpi_metrics
m = query_kpi_metrics(1, 'VP of Revenue (Executive)').kpis['mrr']
print(m.delta_relative_pct, m.z_score)"     # -> -4.0 -17.68
```

## What it does

### Scenario 1 — Multi-Factor Incident

MRR falls **4.0%** to $960,000 (z = −17.7 over a 27-day baseline) while churn
rises **12.0%**. Two causes run at once, and the system ranks them
**arithmetically, not rhetorically**:

| Share | Hypothesis | Driver | Basis |
|---:|---|---|---|
| **92.2%** | internal | Payment gateway timeout (Stripe API v2.2) | `failed_transactions_usd` above 27-day trailing mean |
| **7.8%** | external | Competitor discount campaign | `churned_mrr` above 27-day trailing mean |

Ranking is computed in SQL. The debate explains the causes; it does not decide
their weights.

### Scenario 2 — Abstain

Churn rises 12.0%, and the system declines to say why. Two independent reasons,
both checked in Python:

1. The arbitrator splits **50 / 50** — evidence supports both hypotheses.
2. `churned_mrr` is a single column with **no voluntary/involuntary split**, so
   competitor-driven and payment-driven cancellation are mathematically
   indistinguishable in the warehouse.

The second gate is the interesting one: **even a 90%-confident verdict cannot
pass it.** This is a missing-column problem, not a reasoning problem, and the
system says exactly that instead of guessing.

### Scenario 3 — Sparse History

`payment-gateway-v2` p99 latency hits 3,450 ms, three days after migration. The
semantic contract requires 14 days before a z-score baseline is supportable, so
the watcher **withholds the z-score**, degrades to a bounded range check, marks
the KPI `LOW POWER`, and the arbitrator caps confidence at 72. The finding is
real; the statistical power behind it is not, and the UI says so.

## Persona RBAC — enforced at the query layer

`SEC-04` says hiding a field in the UI is not authorisation. It isn't hidden here.

| | VP of Revenue | Director of Engineering |
|---|---|---|
| MRR | `$960,000` | `[RESTRICTED]` — *query not executed* |
| Churn / Gateway / Latency | visible | visible |
| Driver ranking | shares **and** dollar exposure | shares only |
| Narrative | business impact, commercial action | root cause, rollback procedure |

For the denied persona the `billing_mrr` SELECT never runs, so the value never
enters the process, `st.session_state`, the agent context, or the rendered page.
Four tests assert exactly that, including a raw-string search of the served
markup.

## Documented deviations

Where the source documents disagree with each other, the resolution and its
reason:

1. **Frontend: Streamlit, not Next.js.** PRD `FR-U-01` / `AC-08` specify
   Next.js; TRD `TR-005` mandates Streamlit and lists Next.js as a rejected
   technology. The TRD is the later engineering contract and every build step
   is Streamlit, so `AC-08` is superseded. A React console is Phase 2.

2. **Neo4j feedback is really written.** Build Step 6 deferred persistence to a
   toast. PRD `FR-H-02` / `AC-07` require a real relationship, so
   `db/memory_graph.py` performs the `MERGE`. If no local Neo4j is reachable it
   falls back to `feedback_journal.jsonl` **and the UI says which path it
   took** — it never claims a graph write it did not make.

3. **Action keys.** Python fields are snake_case (they must be identifiers);
   Pydantic aliases serialise to the PRD's canonical keys with spaces, so
   `AC-10` is satisfied literally.

4. **Evidence corpus is 3+3, not 2+2.** Build Step 2 requires two Zendesk
   tickets and two Slack messages; those four are seeded verbatim. One extra of
   each covers the sparse-history scenario so Scenario 3 retrieves real
   evidence instead of unrelated payment documents.

5. **Baseline history.** Build Step 2 fixes the 08-24 and 08-25 rows. 26
   further days are seeded — deterministically, with no RNG — because a z-score
   needs a baseline. The mandated values are exact.

6. **Extra dependencies.** `autogen-ext[openai]` (the model client AutoGen v0.7
   needs), `PyYAML` (semantic contract), and a `googleapis-common-protos` pin
   that resolves a real protobuf conflict between chromadb and autogen-core.
   All documented in `requirements.txt`.

## Known limitations

Stated plainly, because a prototype that hides these is worse than one that
names them.

- **Retrieval quality is the first thing that breaks on real data.** The corpus
  is six curated documents where the relevant evidence is guaranteed present
  and unambiguous. Against a real Slack workspace, agents would argue
  confidently over incomplete evidence.
- **Confidence is an ordinal judgement, not a calibrated probability.** The
  safety property comes from the threshold's location — in Python, failing
  closed — not from calibration. Calibrating it needs outcome data the HITL loop
  has only started collecting.
- **The persona dropdown is not authentication.** It is a demo mechanism, as
  the TRD requires. What is defensible is *where* enforcement sits: data
  selection, not rendering.
- **The memory graph is written but not yet read back** into diagnosis.
  Round 1 promised sub-50 ms structural recall; that is Phase 2.
- **Free-text narrative is the softest surface.** Prompt constraint reduces
  hallucination risk; schema validation does not cover prose. Templating the
  narrative from validated fields is the production answer.
